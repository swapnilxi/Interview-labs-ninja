Claude Haiku 4.5 via Vertex AI & Model Garden — Key Generation & Wiring

You already have LLMConfig and provider detection. Today you add the missing piece that lets Claude Haiku 4.5 answer through Google Cloud: a service-account key, the right environment variables, and a thin vertex_ai provider branch that your existing abstraction can dispatch to.

Learning Objectives

  • Generate a Google Cloud service-account JSON key and enable the Vertex AI API on a project.
  • Understand how Anthropic Claude Haiku 4.5 is reached via Vertex AI Model Garden (not the Anthropic API).
  • Extend LLMConfig.from_env() to detect vertex_ai and load credentials safely.
  • Implement a working _generate_vertex_ai() call against claude-haiku-4-5 and verify it end-to-end.

Why Vertex AI for Claude Haiku 4.5?

In the LCB project, every provider is a route to the same abstract capability: send a prompt, get grounded text back. The Anthropic API is one route. Vertex AI is another — same Claude models, different front door, different auth, different billing, and often different regional latency.

Think of it like shipping a package. The contents (Claude Haiku 4.5) are identical, but you can hand it to the Anthropic courier (API key in a header) or the Google Cloud courier (service-account credentials, project ID, region). Your LLMClient just needs to know which courier to call.

Key Takeaway

Vertex AI is not the Anthropic API. It uses Google IAM, a GCP project ID, and a region (e.g. us-east5). You cannot reuse your ANTHROPIC_API_KEY here — you need a service-account JSON.

Two interchangeable routes to the same Claude Haiku 4.5 model — the abstraction hides the difference.

Implementation

Enable the Vertex AI API & pick a region

Claude models on Vertex live in specific regions. us-east5 is the safest default for Haiku 4.5.

bash 
# Replace with your real project id
export GCP_PROJECT_ID="lcb-rag-prod"

gcloud config set project "$GCP_PROJECT_ID"
gcloud services enable aiplatform.googleapis.com

# Confirm Claude Haiku 4.5 is available in your region
gcloud ai models list --region=us-east5 --filter="displayName:claude-haiku-4-5"

Create a service account & download the JSON key

The service account is the identity your backend will use. It needs the roles/aiplatform.user role — nothing more.

bash 
SA_NAME="lcb-rag-vertex"
SA_EMAIL="${SA_NAME}@${GCP_PROJECT_ID}.iam.gserviceaccount.com"

gcloud iam service-accounts create "$SA_NAME" \
  --display-name="LCB RAG Vertex AI caller"

gcloud projects add-iam-policy-binding "$GCP_PROJECT_ID" \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/aiplatform.user"

# Download the JSON key -- treat this file as a secret
gcloud iam service-accounts keys create ./secrets/vertex-sa.json \
  --iam-account="$SA_EMAIL"
Warning

vertex-sa.json is a long-lived credential. Never commit it. Add secrets/ and *.json (under secrets/) to .gitignore, and in production inject the JSON via your secret manager (GCP Secret Manager, AWS Secrets Manager, or a mounted Kubernetes secret) — not a checked-in file.

Add the Vertex env vars to .env

The credential path is a path, not the JSON itself. This keeps the process env small and lets you swap credentials per environment.

.env 
# --- Vertex AI / Claude Haiku 4.5 on Model Garden ---
LLM_PROVIDER=vertex_ai
VERTEX_PROJECT_ID=lcb-rag-prod
VERTEX_LOCATION=us-east5
VERTEX_MODEL=claude-haiku-4-5@20251001
GOOGLE_APPLICATION_CREDENTIALS=./secrets/vertex-sa.json

# Keep the Anthropic fallback intact
ANTHROPIC_API_KEY=sk-ant-...
FALLBACK_LLM_PROVIDER=ollama
FALLBACK_OLLAMA_MODEL=llama3.2:3b

Teach LLMConfig.from_env() about vertex_ai

Add a detection branch alongside your existing anthropic / claude_code branches. Note that we reuse the base_url field to carry the region — it's the closest semantic fit without changing the frozen dataclass shape.

python 
# backend_fastapi/app/chatbot/llm_client.py
import os
import json
from dataclasses import dataclass
from typing import Optional


@dataclass(frozen=True)
class LLMConfig:
    provider: str
    model: str
    base_url: Optional[str] = None
    api_key: Optional[str] = None
    timeout: int = 120
    temperature: float = 0.2
    max_tokens: int = 1024

    @classmethod
    def from_env(cls) -> "LLMConfig":
        provider = os.getenv("LLM_PROVIDER", "ollama").strip().lower()

        # --- existing branches (Modules 2-3) ---
        if provider in ("anthropic", "claude"):
            return cls(
                provider="anthropic",
                model=os.getenv("ANTHROPIC_MODEL", "claude-haiku-4-5"),
                base_url=os.getenv("ANTHROPIC_BASE_URL", "https://api.anthropic.com"),
                api_key=os.getenv("ANTHROPIC_API_KEY") or os.getenv("CLAUDE_API_KEY"),
                timeout=int(os.getenv("LLM_TIMEOUT", "120")),
                temperature=float(os.getenv("LLM_TEMPERATURE", "0.2")),
                max_tokens=int(os.getenv("LLM_MAX_TOKENS", "1024")),
            )

        if provider in ("claude_code", "claude-code", "claudecode"):
            return cls(
                provider="claude_code",
                model=os.getenv("CLAUDE_CODE_MODEL", "claude-haiku-4-5"),
                base_url=os.getenv("CLAUDE_CODE_WORKSPACE", "."),
                api_key=os.getenv("ANTHROPIC_API_KEY") or os.getenv("CLAUDE_API_KEY"),
                timeout=int(os.getenv("LLM_TIMEOUT", "120")),
                temperature=float(os.getenv("LLM_TEMPERATURE", "0.2")),
                max_tokens=int(os.getenv("LLM_MAX_TOKENS", "1024")),
            )

        # --- NEW: Vertex AI / Model Garden ---
        if provider in ("vertex_ai", "vertex", "google_vertex"):
            project = os.getenv("VERTEX_PROJECT_ID")
            location = os.getenv("VERTEX_LOCATION", "us-east5")
            creds_path = os.getenv("GOOGLE_APPLICATION_CREDENTIALS")

            if not project:
                raise ValueError(
                    "LLM_PROVIDER=vertex_ai requires VERTEX_PROJECT_ID in the environment."
                )
            if not creds_path or not os.path.isfile(creds_path):
                raise ValueError(
                    "LLM_PROVIDER=vertex_ai requires GOOGLE_APPLICATION_CREDENTIALS "
                    "to point at an existing service-account JSON file."
                )

            return cls(
                provider="vertex_ai",
                model=os.getenv("VERTEX_MODEL", "claude-haiku-4-5@20251001"),
                # We store the region here so the generator can read it uniformly.
                base_url=location,
                # Not a real secret -- just the path we resolved.
                api_key=creds_path,
                timeout=int(os.getenv("LLM_TIMEOUT", "120")),
                temperature=float(os.getenv("LLM_TEMPERATURE", "0.2")),
                max_tokens=int(os.getenv("LLM_MAX_TOKENS", "1024")),
            )

        # --- existing ollama / gemini / deepseek / openrouter branches ---
        return cls(
            provider=provider,
            model=os.getenv("OLLAMA_MODEL", "llama3.2:3b"),
            base_url=os.getenv("OLLAMA_BASE_URL", "http://localhost:11434"),
            timeout=int(os.getenv("LLM_TIMEOUT", "120")),
            temperature=float(os.getenv("LLM_TEMPERATURE", "0.2")),
            max_tokens=int(os.getenv("LLM_MAX_TOKENS", "1024")),
        )
Tip

We also need the project id at call time, but the frozen dataclass has no field for it. Two options: (a) add a project: Optional[str] field to the dataclass, or (b) read VERTEX_PROJECT_ID directly in the generator. We'll do (b) here to keep Module 2's dataclass contract unchanged — a good example of backward compatibility.

Implement _generate_vertex_ai()

The Anthropic Python SDK ships a first-class Vertex client. It reads the JSON key from GOOGLE_APPLICATION_CREDENTIALS automatically, so we only need to pass the project and region.

python 
# backend_fastapi/app/chatbot/llm_client.py (continued)
import os
import logging

logger = logging.getLogger(__name__)


class LLMClient:
    def __init__(self, config: Optional[LLMConfig] = None):
        self.config = config or LLMConfig.from_env()

    # --- public API ---
    def generate(self, prompt: str) -> str:
        provider = self.config.provider
        if provider == "anthropic":
            return self._generate_anthropic(prompt)
        if provider == "claude_code":
            return self._generate_claude_code(prompt)
        if provider == "vertex_ai":
            return self._generate_vertex_ai(prompt)
        raise NotImplementedError(f"Unsupported provider: {provider}")

    # --- Vertex AI branch ---
    def _generate_vertex_ai(self, prompt: str) -> str:
        project_id = os.getenv("VERTEX_PROJECT_ID")
        region = self.config.base_url or "us-east5"
        model = self.config.model

        if not project_id:
            raise ValueError("VERTEX_PROJECT_ID is not set.")

        try:
            from anthropic import AnthropicVertex
        except ImportError as exc:
            raise RuntimeError(
                "anthropic[vertex] is not installed. Run: "
                "pip install \"anthropic[vertex]\" google-cloud-aiplatform"
            ) from exc

        # AnthropicVertex picks up GOOGLE_APPLICATION_CREDENTIALS automatically.
        client = AnthropicVertex(project_id=project_id, region=region)

        logger.info(
            "vertex_ai call | project=%s region=%s model=%s",
            project_id, region, model,
        )

        message = client.messages.create(
            model=model,
            max_tokens=self.config.max_tokens,
            temperature=self.config.temperature,
            messages=[{"role": "user", "content": prompt}],
        )

        # Same response shape as the direct Anthropic API.
        return message.content[0].text.strip()
Deep Dive

The @20251001 suffix on the model name is a Vertex version pin. Unlike the Anthropic API where the date is baked into the model id itself, Vertex exposes Claude Haiku 4.5 under versioned aliases. If you get a 404 on claude-haiku-4-5@20251001, list the models available in your region with: gcloud ai models list --region=us-east5 and pick the newest Haiku 4.5 alias you see.

Failure-mode checks

  • Unset VERTEX_PROJECT_ID → expect ValueError: ... requires VERTEX_PROJECT_ID.
  • Point GOOGLE_APPLICATION_CREDENTIALS at a missing file → expect ValueError from from_env().
  • Wrong region (e.g. us-central1 for Haiku 4.5) → expect a 404 from the SDK; the log line shows the region you sent.
  • Delete the key file after loading → SDK raises a credentials error; confirms we're not caching secrets in memory.

Key Takeaways

  • Vertex AI is a distinct provider from the Anthropic API — different auth, project, and region.
  • You need a service-account JSON with roles/aiplatform.user; the API key from Anthropic will not work.
  • LLMConfig.from_env() now has a vertex_ai branch that validates project + credentials file before returning.
  • _generate_vertex_ai() uses AnthropicVertex(project_id, region) and returns the same message.content[0].text shape as the direct Anthropic branch.
  • Never commit the JSON key — use .gitignore locally and a secret manager in production.
  • Two new unit tests lock in the failure modes (missing project, missing credentials file).
