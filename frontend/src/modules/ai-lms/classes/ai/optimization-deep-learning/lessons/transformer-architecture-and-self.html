Transformer Architecture and Self-Attention

The neural network design that made modern LLMs possible — and the attention math that lets every token look at every other token at once.

What you'll learn

  • Why the Transformer replaced recurrence, and what problem self-attention actually solves.
  • How Query, Key, and Value projections produce a weighted context vector for each token.
  • The role of multi-head attention, positional encoding, and the residual + layer-norm block.
  • Where Transformers sit in the modern LLM stack — and where their compute cost comes from.

Why Transformers exist

Before 2017, sequence models were dominated by RNNs and LSTMs. They processed tokens one at a time, carrying a hidden state left to right. That works, but it has two stubborn problems: it's sequential (you can't parallelize across time steps on a GPU), and long-range information gets squeezed through a fixed-size hidden state, so it fades.

The Transformer (Vaswani et al., “Attention Is All You Need”, 2017) threw out recurrence entirely. Instead, every token is projected into a representation and then allowed to directly attend to every other token in the sequence. One matrix multiply replaces a whole chain of sequential steps.

Analogy

Think of a room full of people at a conference. In an RNN, each person can only whisper to the person next to them, and news travels down the line. In a Transformer, everyone can hear everyone simultaneously — and each person decides how much to listen to each other person based on relevance.

Anatomy of one Transformer block

A Transformer is a stack of identical blocks. Each block has two sublayers: a multi-head self-attention layer and a position-wise feed-forward network. Both are wrapped with a residual connection and layer normalization.

One Transformer block. Stack N of these — GPT-style models use 12 to 100+.

Self-attention, step by step

Self-attention is a soft, learned lookup. For every token, we compute three vectors by multiplying its embedding with learned weight matrices:

  • Query (Q) — "what am I looking for?"
  • Key (K) — "what do I offer?"
  • Value (V) — "what information do I carry?"

We then score each query against every key with a dot product, scale by 1/√d_k to keep gradients stable, apply softmax to get attention weights, and take a weighted sum of the values.

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
Deep dive — why divide by √d_k?

Dot products of high-dimensional vectors grow with d_k. Without scaling, the softmax saturates — one weight goes to ~1, the rest to ~0 — and gradients vanish. Dividing by √d_k keeps the scores in a range where softmax produces useful, non-degenerate distributions.

Multi-head attention

A single attention head can only learn one "type" of relationship. Multi-head attention runs h attention operations in parallel with different learned projections, then concatenates and projects the results. One head might track syntactic dependencies ("cat" → "sat"), another might track coreference ("it" → "the mat"), another might track position.

Positional encoding

Attention is permutation-invariant — it has no built-in sense of order. Without help, "dog bites man" and "man bites dog" would look identical. Positional encodings (sinusoidal, learned, or rotary) are added to token embeddings so the model knows where each token sits.

Encoder vs. decoder

Variant Attention Typical use
Encoder-only Bidirectional (every token sees every token) BERT — classification, embeddings, RAG reranking
Decoder-only Causal (each token sees only prior tokens) GPT, Llama, Claude — generation, chat, agents
Encoder–decoder Bidirectional encoder + causal decoder with cross-attention T5, translation, summarization
Cost warning

Self-attention is O(n²) in sequence length — for each of n tokens you score against n keys. Doubling context length quadruples the attention compute and memory. This is why long-context models use tricks like FlashAttention, sliding-window attention, or grouped-query attention.

Self-attention in code

A minimal, dependency-free implementation of scaled dot-product attention:

Python 
import numpy as np

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)   # stability
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def scaled_dot_product_attention(Q, K, V, mask=None):
    # Q, K, V: (batch, seq_len, d_k)
    d_k = Q.shape[-1]
    scores = Q @ K.transpose(0, 2, 1) / np.sqrt(d_k)

    if mask is not None:
        # causal mask: -inf for future positions
        scores = np.where(mask, scores, -1e9)

    weights = softmax(scores, axis=-1)
    return weights @ V, weights

And a full multi-head attention module — the workhorse inside every LLM block:

Python 
import torch
import torch.nn as nn

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.d_model = d_model
        self.n_heads = n_heads
        self.d_head  = d_model // n_heads
        self.qkv  = nn.Linear(d_model, 3 * d_model)
        self.proj = nn.Linear(d_model, d_model)

    def forward(self, x, causal=True):
        B, T, C = x.shape
        qkv = self.qkv(x)                           # (B, T, 3C)
        q, k, v = qkv.chunk(3, dim=-1)

        # split into heads: (B, n_heads, T, d_head)
        shape = (B, T, self.n_heads, self.d_head)
        q, k, v = [t.view(shape).transpose(1, 2) for t in (q, k, v)]

        # scaled dot-product attention
        att = (q @ k.transpose(-2, -1)) / (self.d_head ** 0.5)
        if causal:
            mask = torch.tril(torch.ones(T, T, device=x.device))
            att = att.masked_fill(mask == 0, float('-inf'))
        att = torch.softmax(att, dim=-1)
        out = att @ v                                 # (B, h, T, d_head)

        # merge heads and project
        out = out.transpose(1, 2).contiguous().view(B, T, C)
        return self.proj(out)

Key takeaways

  • Transformers replace sequential recurrence with parallel self-attention, unlocking GPU efficiency and long-range context.
  • Each token is projected into Query, Key, and Value vectors; attention is a soft, learned lookup over the sequence.
  • The scaling factor 1/√d_k is not cosmetic — it keeps softmax gradients healthy.
  • Multi-head attention lets different heads specialize on different relationship types.
  • Positional encodings inject order, since attention itself is permutation-invariant.
  • Cost is O(n²) in sequence length — the central bottleneck for long-context LLMs.
Where this fits

Every modern LLM — the ones powering chat assistants, RAG pipelines, and multi-agent frameworks like LangGraph and CrewAI — is a stack of Transformer blocks. Understanding attention is the prerequisite for reasoning about context windows, KV-cache memory, prompt length costs, and why retrieval augmentation exists at all.
