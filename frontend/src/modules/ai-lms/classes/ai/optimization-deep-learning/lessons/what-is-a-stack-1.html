What is a Stack?

A 10-minute, hands-on tour of the LIFO data structure — the same primitive that powers call stacks, undo buffers, DFS traversal, and the token/state bookkeeping inside modern LLM agent runtimes.

LIFO discipline O(1) push / pop / peek Interactive visualizer 2 quiz questions

1 · The intuition

A stack is a linear collection with a single rule: you can only add or remove items from one end, called the top. That rule gives it the name LIFO — Last In, First Out.

Think of a stack of plates. You put a new plate on top. You take the top plate off. You never reach into the middle.

Why it matters in AI engineering: every Python function call you make inside a LangGraph node runs on the interpreter's call stack. Every recursive DFS over a tool-call tree is literally a stack. And many agent runtimes keep an explicit history stack of turns so they can pop back to a previous state.

2 · The three core operations

push(x)

Add x on top of the stack. The stack grows by one.

pop()

Remove and return the top element. Errors (or returns None) if empty.

peek() / top()

Return the top element without removing it.

Supporting queries

is_empty() and size().

Reference implementation (Python)

class Stack:
    def __init__(self):
        self._items = []          # list = dynamic array

    def push(self, x):
        self._items.append(x)     # O(1) amortized

    def pop(self):
        if not self._items:
            raise IndexError("pop from empty stack")
        return self._items.pop()  # O(1)

    def peek(self):
        return self._items[-1] if self._items else None

    def is_empty(self):
        return not self._items

    def __len__(self):
        return len(self._items)

Note: append and pop on the end of a Python list are O(1) amortized. Popping from the front (pop(0)) is O(n) — that's a queue problem, not a stack problem.

Common bug to avoid: calling pop() or peek() on an empty stack. Always guard with is_empty() — this is the same class of bug as indexing an empty list in your RAG pipeline.

* Amortized, when backed by a dynamic array that occasionally doubles.

Two ways to build it

Array-backed: fast, cache-friendly, amortized O(1) push. Best default choice.

Linked-list-backed: strict worst-case O(1) push/pop, but extra pointer overhead and worse cache locality.
