01 What is a stack?

A stack is a linear data structure that follows the LIFO principle: Last In, First Out. Think of a stack of plates at a cafeteria — you can only add a plate to the top, and you can only take a plate from the top.

Two rules, that's it

  • push(x) — add x to the top.
  • pop() — remove and return the element at the top.

Everything else — peek(), isEmpty(), size() — is sugar on top of those two.

Where you already meet them

  • The call stack in every running program.
  • The undo history in your editor.
  • Bracket matching in compilers.
  • DFS traversal in graphs and trees.
  • The tool-call stack in an LLM agent loop.
Mental model: a stack is a discipline, not a shape. You can implement one with an array, a linked list, or a Python list — the LIFO contract is what makes it a stack.

04 Code — three ways to say the same thing

Python — the one-liner version

python# Python's list IS a stack if you use it correctly.
stack = []

stack.append("A")   # push
stack.append("B")   # push
top = stack[-1]      # peek  -> "B"
top = stack.pop()       # pop   -> "B"

if not stack:
    print("empty!")

JavaScript — array as stack

javascriptconst stack = [];

stack.push("A");            // push
stack.push("B");            // push
const top = stack[stack.length - 1]; // peek
const popped = stack.pop(); // pop -> "B"

TypeScript — an explicit Stack class

typescriptclass Stack<T> {
  private items: T[] = [];

  push(x: T): void { this.items.push(x); }

  pop(): T | undefined {
    if (this.isEmpty()) throw new Error("pop from empty stack");
    return this.items.pop();
  }

  peek(): T | undefined {
    return this.items[this.items.length - 1];
  }

  isEmpty(): boolean { return this.items.length === 0; }
}

05 Why stacks feel free

Time

O(1) per op

push, pop, peek — all constant time. No searching, no shifting.

Space

O(n)

One slot per element. Nothing more.

Shape

Linear, restricted

You can't reach the middle. That restriction is the feature.

Design lesson: a stack is powerful because of what it forbids. By removing random access, it makes certain algorithms — DFS, backtracking, parsing — trivially correct.

06 The stack you'll meet inside an AI agent

This is where the lesson stops being "intro CS" and starts being your daily job.

Where LIFO hides in modern LLM systems

Agents Tool-call stacks. When an agent calls a tool that calls another tool, the runtime pushes a frame per call and pops on return — exactly like a program's call stack.

LangGraph Checkpoint stacks. Each graph step can be pushed onto a checkpoint stack so you can pop back to a prior state (a "time-travel" undo).

RAG Context assembly. Retrieved chunks are often pushed onto a bounded stack; when the token budget fills, the top (most recent) chunks survive.

Evaluation Trace unwinding. An eval harness pops the last span to attribute cost / latency to the innermost call — LIFO in a profiler.

Recursion is the bridge. Backpropagation, DFS over a computation graph, and an agent's recursive tool-use loop are the same shape: push a frame, recurse, pop the frame, combine the result. If you understand a stack, you understand the skeleton of every one of them.
