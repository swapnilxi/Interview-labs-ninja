The Stack: Last In, First Out

A stack is the simplest useful data structure you'll ever meet. It stores items in order, but only lets you touch one end — the top. Push to add, pop to remove. That's it. And that tiny constraint quietly powers function calls, undo buttons, expression parsers, and the recursive backpropagation loops inside every deep learning framework.

1 The Core Idea

Imagine a stack of plates in a cafeteria. You can only add a plate to the top, and you can only take a plate from the top. You can't pull one out of the middle without lifting everything above it first.

That's the entire contract. A stack is a LIFO structure — Last In, First Out. The most recently added item is the first one you can remove.

The three operations:
  • push(x) — add x to the top.
  • pop() — remove and return the top item.
  • peek() — look at the top item without removing it.

Why it matters

  • Function call frames live on a stack.
  • Undo/redo in editors is a pair of stacks.
  • Balanced-parentheses checks use a stack.
  • Depth-first search (DFS) is a stack in disguise.
  • Reverse Polish notation evaluation uses a stack.

2 Under the Hood

A stack is an interface, not a specific memory layout. Two common implementations:

Array-backed

Store items in a dynamic array. The top is the last index. push/pop are O(1) amortized. Cache-friendly and simple.

Linked-list-backed

Each node points to the one below it. The head is the top. O(1) push/pop with no resizing, but extra pointer overhead per item.

A minimal Python stack

class Stack:
    def __init__(self):
        self._items = []          # list is our backing store

    def push(self, x):
        self._items.append(x)     # add to the top

    def pop(self):
        if self.is_empty():
            raise IndexError("pop from empty stack")
        return self._items.pop()   # removes last item

    def peek(self):
        return self._items[-1] if self._items else None

    def is_empty(self):
        return not self._items
Edge case: popping an empty stack is a bug in most languages. Always check is_empty() first — or catch the exception. This is exactly the kind of thing that turns a stack overflow into a crash.

3 A Real Example: Balanced Parentheses

Given a string of brackets like "([{}])", decide if every opening bracket has a matching closer in the right order. A stack solves this in one pass. 

def is_balanced(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = Stack()

    for ch in s:
        if ch in "([{":
            stack.push(ch)
        elif ch in pairs:
            if stack.is_empty() or stack.pop() != pairs[ch]:
                return False

    return stack.is_empty()

# is_balanced("([{}])") -> True
# is_balanced("([)]")   -> False

Every opening bracket is pushed. Every closing bracket must match the most recent unmatched opener — which is, by definition, the top of the stack.

5 Cheat Sheet

Operations & Complexity

  • push(x) — O(1) amortized
  • pop() — O(1)
  • peek() — O(1)
  • is_empty() — O(1)

Common Pitfalls

  • Popping an empty stack.
  • Assuming you can index into the middle.
  • Confusing a stack (LIFO) with a queue (FIFO).
  • Forgetting that recursion uses the call stack implicitly.
