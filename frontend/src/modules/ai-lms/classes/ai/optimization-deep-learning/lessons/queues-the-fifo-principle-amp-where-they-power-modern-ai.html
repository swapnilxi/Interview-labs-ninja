Queues: The FIFO Principle & Where They Power Modern AI

A queue is a linear data structure that stores elements in order and releases them in the exact same order they arrived — First In, First Out. It sounds almost too simple to matter. Yet queues are the invisible machinery behind request batching for LLM inference, streaming tokens, task scheduling for agents, and the message buses that glue multi-agent systems together.

01 What is a Queue?

A queue is an abstract data type (ADT) that models a waiting line. You add items at one end and remove them from the other. The end where items are added is the rear (or tail); the end where items are removed is the front (or head).

One-line definition: A queue is a collection where the element that has been waiting the longest is the next one to be served.

Contrast this with a stack (LIFO — Last In, First Out), where the most recently added item is removed first. The difference is small in words, but it changes the behavior of entire algorithms: BFS uses a queue, DFS uses a stack.

Everyday mental models

  • 🧾 A checkout line — the first customer to arrive is served first.
  • 🖨️ A printer spooler — print jobs are printed in the order they were submitted.
  • 🎟️ A ticket counter — take-a-number systems preserve arrival order.
  • 🤖 An LLM inference server — prompts are processed in arrival order (or in fair batches).

02 The FIFO Contract

FIFO is not just a description — it's a contract that the data structure guarantees. If you enqueue A, B, C in that order, then dequeue operations must return A, then B, then C. No reordering. No skipping.

Items enter at the rear and leave from the front — the defining FIFO motion.

03 Core Operations & Complexity

A queue exposes a small, focused set of operations. The whole point is that you cannot reach into the middle.

OperationMeaningTime
enqueue(x)Add x at the rearO(1)
dequeue()Remove & return the front elementO(1)
peek() / front()Read the front without removingO(1)
isEmpty()True if no elements remainO(1)
size()Number of elements currently queuedO(1)
Why O(1) matters: In high-throughput AI systems, a queue may process millions of requests per second. If dequeue were O(n) — as it is in a naive list implementation — the whole pipeline would stall. Constant-time operations are what make queues the backbone of schedulers and stream processors.

Overflow & underflow

  • Overflow — enqueueing into a full bounded queue. Real systems handle this with backpressure, blocking, or rejection.
  • Underflow — dequeueing from an empty queue. Always guard with isEmpty().

05 How Queues Are Implemented

A queue is an interface. Underneath, it can be built from several different structures, each with trade-offs. The three most common are the circular buffer, the linked list, and the double-ended queue (deque).

Circular buffer (ring buffer)

A fixed-size array with head and tail indices that wrap around using modulo arithmetic. Cache-friendly and allocation-free — the workhorse of high-performance systems.

Linked list

Each node points to the next. Enqueue at tail, dequeue at head, both O(1). Grows unbounded without copying, but pointer chasing hurts cache locality.

Reference implementation — circular buffer (Python)

pythonclass CircularQueue:
    def __init__(self, capacity: int):
        self._buf = [None] * capacity
        self._cap = capacity
        self._head = 0      # index of the front element
        self._size = 0      # number of stored elements

    def enqueue(self, x) -> None:
        if self._size == self._cap:
            raise OverflowError("queue is full")
        tail = (self._head + self._size) % self._cap
        self._buf[tail] = x
        self._size += 1

    def dequeue(self):
        if self._size == 0:
            raise IndexError("queue is empty")
        x = self._buf[self._head]
        self._head = (self._head + 1) % self._cap
        self._size -= 1
        return x

    def peek(self):
        if self._size == 0:
            raise IndexError("queue is empty")
        return self._buf[self._head]

Idiomatic usage — collections.deque

pythonfrom collections import deque

q = deque()
q.append("prompt_1")      # enqueue at rear
q.append("prompt_2")
q.append("prompt_3")

first = q.popleft()      # dequeue from front — O(1)
print(first)             # prompt_1  (FIFO!)
Common pitfall: Using a plain Python list and calling pop(0). That's O(n) because every remaining element shifts left. Always use deque for queues.

06 Common Uses of Queues

Queues appear wherever order of arrival must be preserved and work must be processed fairly.

  1. Breadth-First Search (BFS) — explore a graph level by level. The queue guarantees nodes are visited in increasing distance from the source.
  2. Task scheduling — operating systems, thread pools, and job runners dispatch work in FIFO order.
  3. Message queues — Kafka, RabbitMQ, SQS. Producers enqueue, consumers dequeue, decoupling systems.
  4. Buffering & streaming — video/audio playback, network packet buffers, and token streams all rely on queues.
  5. Print spoolers & I/O — devices process requests in the order received.
  6. Rate limiting & fair scheduling — round-robin schedulers rotate through a queue of ready tasks.
  7. Producer–consumer pipelines — a bounded queue synchronizes fast producers with slow consumers.

BFS in one picture

BFS visits nodes in the order they enter the queue — level by level, guaranteed by FIFO.

BFS skeleton

pythonfrom collections import deque

def bfs(graph, start):
    visited = {start}
    q = deque([start])           # enqueue the source

    while q:
        node = q.popleft()       # dequeue front — FIFO
        print(node)
        for nbr in graph[node]:
            if nbr not in visited:
                visited.add(nbr)
                q.append(nbr)    # enqueue at rear

07 Queues in Modern AI Systems

If you're building with LLMs, RAG, or agents, you're already using queues — you just may not have named them. Here's where FIFO discipline shows up in production AI stacks:

LLM inference batching
Incoming prompts land in a request queue. The inference server pulls a batch from the front, runs the model, and streams tokens back. FIFO (or fair-share variants) keeps latency predictable.
Streaming token output
Tokens generated by the model are enqueued and flushed to the client in order. Reordering would scramble the sentence.
Agent task queues
In LangGraph or CrewAI, tasks handed to workers are often queued. A worker dequeues a task, executes it, and enqueues follow-ups.
Message buses in multi-agent systems
Agents communicate via queues (Kafka, Redis Streams). Each message is delivered in order, enabling deterministic replay and audit.
RAG ingestion pipelines
Documents to embed and upsert into a vector store flow through a queue. Backpressure prevents the embedding service from being overwhelmed.
Evaluation harnesses
Test prompts are queued, run through the model, and scored in order — making results reproducible run-to-run.

Mini example — a token stream queue

pythonfrom collections import deque

# Simulate tokens arriving from an LLM and being flushed in order.
token_queue = deque()

def emit(token: str):
    token_queue.append(token)      # producer enqueues

def flush_one():
    if token_queue:
        return token_queue.popleft()  # consumer dequeues — FIFO
    return None

for t in ["Queues", "preserve", "order."]:
    emit(t)

while token_queue:
    print(flush_one(), end=" ")
# Queues preserve order.
Key insight: FIFO isn't just about fairness — it's about determinism. When order is preserved, systems become reproducible, debuggable, and safe to replay. That property is gold in AI pipelines.
