The Stack: Last In, First Out

A stack is the simplest, most disciplined data structure in computer science. You only ever touch one end — the top. Push to add, pop to remove, peek to look. That single rule gives us function call frames, undo history, expression parsing, and the backtracking that powers everything from compilers to DFS.

1 Intuition — the plate stack

Picture a stack of plates in a cafeteria. You add a plate to the top. You take a plate from the top. You never pull a plate from the middle — that would collapse the pile.

That single constraint is the whole data structure. The last plate you put down is the first one you pick up. Hence the acronym: LIFO — Last In, First Out.

Key insight: A stack is not a bag you rummage through. It's a discipline that forces order onto your operations. That discipline is exactly what makes recursion, undo, and parsing work.

2 Anatomy of a stack

A stack has exactly three moving parts, no matter how it's implemented:

1. Storage

Where the elements live. Usually an array (fast, cache-friendly) or a linked list (unbounded, no resize cost).

2. Top pointer

An index or reference that tracks the current top. Everything happens relative to it.

3. The LIFO contract

Only three legal operations: push, pop, peek. No random access. No insertion in the middle.

Overflow & underflow: pushing onto a full fixed-size stack → overflow. popping from an empty stack → underflow. Real implementations either grow dynamically or raise an error.

3 The core operations

Operation What it does Time Space
push(x) Add x to the top O(1) amortized O(1)
pop() Remove & return the top O(1) O(1)
peek() Return top without removing O(1) O(1)
isEmpty() Check if stack has elements O(1) O(1)
Why O(1) matters: Because every operation touches only the top, stacks are the fastest possible container for LIFO workloads. This is why the call stack of your program is a stack — millions of pushes and pops per second with no overhead.

5 Implementation

Array-backed stack (Python)

pythonclass Stack:
    def __init__(self):
        self._data = []          # storage

    def push(self, x):
        self._data.append(x)     # O(1) amortized

    def pop(self):
        if not self._data:
            raise IndexError("pop from empty stack")
        return self._data.pop()  # O(1)

    def peek(self):
        if not self._data:
            raise IndexError("peek from empty stack")
        return self._data[-1]

    def is_empty(self):
        return not self._data

    def __len__(self):
        return len(self._data)

Usage — balanced parentheses

pythondef is_balanced(s: str) -> bool:
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = Stack()
    for ch in s:
        if ch in "([{":
            stack.push(ch)
        elif ch in pairs:
            if stack.is_empty() or stack.pop() != pairs[ch]:
                return False
    return stack.is_empty()

# is_balanced("({[]})") → True
# is_balanced("([)]")   → False
The stack remembers what opened so we can match it when it closes. This is the same pattern compilers use to parse your code.
