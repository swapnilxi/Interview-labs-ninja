01 What is a Stack?

A stack is a linear data structure that stores elements in a specific order and only allows you to interact with one end — the top.

Think of a stack of plates in a cafeteria. You can only add a new plate to the top, and you can only take a plate from the top. You cannot pull a plate out from the middle without first removing everything above it.

That single constraint — only touch the top — is what makes the stack so powerful. It enforces a strict, predictable order of operations that turns out to be exactly what many algorithms need.

💡

Definition: A stack is an abstract data type (ADT) that supports two primary operations — push (add to top) and pop (remove from top). The most recently added element is always the first one removed.

02 The LIFO Principle

Stacks follow a rule called LIFO — Last In, First Out. The last element you pushed is the first element you can pop.

This is the opposite of a queue, which is FIFO — First In, First Out (like a line at a coffee shop).

Push adds to the top; pop removes from the top. Only the top element is accessible.

03 Core Operations

Despite its simplicity, a stack has a small but essential set of operations. Every other operation you might want is built from these.

Operation Description Returns
push(x) Add element x to the top of the stack Nothing (or new size)
pop() Remove and return the top element The removed element
peek() / top() Return the top element without removing it The top element
isEmpty() Check whether the stack has any elements Boolean
size() Return the number of elements in the stack Integer
⚠️

Stack Underflow: Calling pop() or peek() on an empty stack is an error. Always check isEmpty() first, or catch the exception — depending on your language.

05 Implementation

Stacks are so simple they can be built on top of an array or a linked list. Here's a clean JavaScript implementation using an array under the hood.

JavaScriptclass Stack {
  constructor() {
    this.items = [];
  }

  // Add an element to the top
  push(value) {
    this.items.push(value);
    return this.items.length;
  }

  // Remove and return the top element
  pop() {
    if (this.isEmpty()) throw new Error("Stack underflow");
    return this.items.pop();
  }

  // Look at the top without removing it
  peek() {
    if (this.isEmpty()) throw new Error("Stack is empty");
    return this.items[this.items.length - 1];
  }

  isEmpty() {
    return this.items.length === 0;
  }

  size() {
    return this.items.length;
  }
}

// Usage
const s = new Stack();
s.push("A");
s.push("B");
s.push("C");
console.log(s.pop());   // "C" — last in, first out
console.log(s.peek());  // "B" — top of the stack now

Notice how the array's native push and pop methods map directly to the stack's operations — this is why arrays are the natural backing store for stacks in most languages.

06 Complexity Analysis

Stacks are prized for their efficiency. Every core operation runs in constant time.

Operation Time Space Why
push O(1) O(1) Append to the end of an array
pop O(1) O(1) Remove from the end of an array
peek O(1) O(1) Direct index lookup
isEmpty O(1) O(1) Length check
search O(n) O(1) Must scan elements (not a native op)
⚡

Why O(1) matters: Because push and pop are constant time, stacks can process millions of operations per second. That's why they're used in tight loops like expression parsing and recursive function calls.

07 Real-World Uses

Stacks aren't just a classroom exercise — they're everywhere in real systems.

📞

The Call Stack

Every function call in your program pushes a new frame. When the function returns, its frame is popped. This is how recursion works.

↩️

Undo / Redo

Text editors and design tools push each action onto an undo stack. Pressing Ctrl+Z pops the last action to reverse it.

🌐

Browser History

Visited pages are pushed onto a stack. The back button pops the current page and reveals the previous one.

🧮

Expression Evaluation

Compilers use stacks to convert infix expressions (like 3 + 4 * 2) into postfix and evaluate them.

🔍

Depth-First Search

DFS traverses graphs and trees using a stack (explicitly or via recursion) to explore one path fully before backtracking.

🔤

Balanced Brackets

Checking if ({[()]}) is valid uses a stack: push openers, pop and match on closers.

08 Stacks vs. Queues

Stacks and queues are often taught together because they're both linear structures with restricted access — but their access rules are opposite.

Stack · LIFO

  • Access at one end (top)
  • Last in, first out
  • Used for: undo, DFS, parsing, call stack
  • Operations: push, pop, peek

Queue · FIFO

  • Access at two ends (front & back)
  • First in, first out
  • Used for: BFS, task scheduling, message queues
  • Operations: enqueue, dequeue, front

If you can remember one image: a stack of plates is a stack, and a line at a checkout counter is a queue.
